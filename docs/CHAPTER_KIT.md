# 章の書き方（執筆キット）

あなたは「世界美術史 ─ 展覧会がもっと面白くなる読み物」の**1章ぶん**を書く。
必ず先に **`chapters/17-impressionism.html`（見本の章）を読むこと。** 構造・語り口・部品の使い方は、
すべてあれに倣う。この文書はそこに書ききれない決まりごとを補うもの。

---

## 1. 読者と語り口

- 読者：美術館・展覧会めぐりが好きな日本語話者の社会人。専門家ではないが、子ども扱いされると腹が立つ。
- **教科書ではなく読み物。** 「〜が挙げられる」「〜と言えよう」のような論文調は使わない。
- 語り口の基本は **「なぜそうなったのか」**。様式名の羅列ではなく、時代のドラマとして語る。
  作品が「どう分類されるか」ではなく、「なぜその人はそう描かざるを得なかったか」を書く。
- 具体を出す。日付、金額、寸法、固有名詞、当時の給料、批評家の実際の悪口。抽象語より具体名。
- 断定できないことは断定しない。「〜と伝わる」「諸説ある」と正直に書く。
- 1文が長くなりすぎない。読点でつなぎ続けない。
- 見出しは「01 チューブが画家を外へ出した」のように、**内容が想像できる短い文**にする。
  「概要」「特徴」「影響」のような無内容な見出しは禁止。

**分量：本文タグを除いた文字数で 4,000〜5,500字。** 見本の章は約4,000字。それ以上、上限まで書いてよい。

## 2. ファイルの作り方

`chapters/<slug>.html` を1枚のHTMLとして書く。見本をコピーして中身を入れ替えるのが早い。

```html
<body class="era-XXXX" data-chapter="<slug>" data-root="../">
```
- `era-XXXX` は `data/chapters.json` のその章の `era` の値をそのまま使う（時代色が決まる）。
- `data-chapter` は slug と完全一致させる（章送りが動く）。
- `<head>` の `<title>` は `第N章　タイトル ─ 世界美術史`。
- CSS・JSの相対パスは見本と同一（`../assets/...`）。**変えない。**

### 章の骨格（この順序を守る）
1. **`header.portal`** — 章扉（門）。**ページを開いた瞬間、その時代しか見えない面**にする
2. `.prose` — 本文。`p.lead`（1段落目、飾り文字が付く）から始める
3. **`.band.spot`（この時代の見分け方）** ← **必須。省略禁止**
4. `h2` を **4〜6本**。`<span class="n">01</span>` の連番を必ず付ける
5. 図版 `figure.plate` を **5〜9点**
6. `.chrono`（この章の年表、5〜8項目）
7. `.meanwhile`（同じころ、世界では）
8. **`.faces`（この時代の顔）** ← **必須。省略禁止**
9. `.seeit`（この章の作品を見に行く）← **必須。省略禁止**
10. `.next`（次章への引き）
11. `details.sources`

### 章扉（門）の書き方

```html
<header class="portal">
  <svg class="portal-art" viewBox="0 0 1000 700" preserveAspectRatio="xMidYMid slice"
       role="img" aria-label="…"> … その時代の面を描く … </svg>
  <div class="bignum" aria-hidden="true">1144</div>
  <div class="inner">
    <p class="chno">第 7 章</p>
    <h1>光の建築</h1>
    <p class="sub">ゴシック　1140 — 1500年</p>
    <p class="lede">…</p>
    <div class="meta"><span><b>舞台</b>　…</span><span><b>顔料</b>　…</span><span><b>読了</b>　約14分</span></div>
  </div>
</header>
```
- `.portal-art` は**その時代そのものの面**。中世ならステンドグラス、日本なら料紙、
  20世紀なら幾何学と原色。**ここは本文ではないので、思い切り振ってよい**
- 地が暗い門にするときは、`header` の `style` で
  `--portal-ink:#e8e3d8; --portal-sub:#a49c8e; --portal-rule:rgba(255,255,255,.2)` のように上書きする
- **章題は必ず最初の画面に入れること。** 装飾が題を追い出してはいけない

### この時代の見分け方（必須）

**装飾ではなく本文の一部**であり、美術史の学習そのもの。
**読者が美術館・寺社・大聖堂の前に立ったとき、実際に使える形**にする。

```html
<div class="band spot">
  <span class="band-label">この時代の見分け方</span>
  <div class="spot-grid">
    <div class="spot-card">
      <div class="fig"><svg viewBox="0 0 200 130" role="img" aria-label="…"> … </svg></div>
      <h4>尖ったアーチ<span class="yomi">ポインテッド・アーチ</span></h4>
      <p>アーチの頂点がとがっていれば、まずゴシック。半円ならその前のロマネスクです。</p>
      <span class="where">どこで見るか ─ 正面の扉口</span>
    </div>
    … あと2枚 …
  </div>
</div>
```
- **3枚**。各20〜40字で「これがあれば◯◯」と**言い切る**
- 図は**比較図が効く**（半円アーチと尖頭アーチを同じ幅で並べて高さの差を示す、など）
- `.where` に「どこで見るか」を添えるとさらに効く

### この時代の顔（必須）

章末の名作ギャラリー。**作品そのものを味わう場所**。

```html
<div class="faces">
  <span class="band-label">この時代の顔</span>
  <div class="faces-grid">
    <figure class="face" data-art="ART_ID">
      <div class="mount"><svg class="fallback" viewBox="0 0 300 240"> … </svg></div>
      <figcaption>
        <span class="artist">クロード・モネ</span>
        <span class="title">印象、日の出<span class="year">1872</span></span>
        <span class="hook">白黒写真にすると、この太陽は消える。明るさが周りとほぼ同じだから。</span>
        <span class="where">マルモッタン・モネ美術館（パリ）</span>
      </figcaption>
    </figure>
    … 全部で6〜10点 …
  </div>
</div>
```
- **6〜10点**。その時代を代表する名作を
- `.hook` が肝。**25〜45字、一文。様式の説明ではなく、その一点にしか言えない事実をひとつだけ**。
  「モネは駅長に頼んで石炭を焚かせた」「この木漏れ日は当時、病気の斑と酷評された」のように、
  読んだ人の目が絵に戻る一行にする。解説に流れそうになったら切る
- `data-art` のIDは本文の図版と重複してよい（同じ作品を再掲するのは構わない）
- ここに出す作品も `data/art/<slug>.json` に登録すること

### 使える部品（見本にすべて実例がある）
`figure.plate` / `.plate-pair` / `.band.compare`（様式比較）/ `.band.person`（人物カード）/
`.band.myth`（通説チェック）/ `.band.chrono` / `.band.meanwhile` / `.band.seeit` / `.pull`（引き句）/
`.quote` / `.term`（用語ツールチップ）

**新しいCSSクラスを発明しない。`<style>` を章に書かない。** 足りない表現は既存の部品で組む。
どうしても必要なときだけ、インライン `style` を短く使う（見本の色見本のように）。

## 3. 図版のきまり ─ ここが一番大事

図版はこのサイトの主役。**1章あたり5〜9点**、本文の流れに沿って置く。

```html
<figure class="plate" data-art="ART_ID">
  <div class="mount">
    <svg class="fallback" viewBox="0 0 600 460" role="img" aria-label="…の構図図解"> … </svg>
  </div>
  <figcaption>
    <span class="artist">作者名（日本語表記）</span>
    <span class="title">作品名<span class="year">制作年</span></span>
    <span class="spec">技法・素材　寸法　所蔵館（都市）</span>
    <span class="look">ここを見る ─ …</span>
  </figcaption>
</figure>
```

- `data-art` は **半角英小文字とハイフンだけ**の一意なID（例 `monet-impression-sunrise`）。
- `.mount` の中の `<svg class="fallback">` は、**作品写真が取得できなかったときだけ**表示される保険。
  構図と色調を抽象化した色面を、あなたが描く。**グレーの箱は禁止。**実作品の複製ではなく抽象。
  viewBox は実作品の縦横比に合わせる。20〜60行程度でよい。
- `.look`（「ここを見る ─」）は**全図版に必ず付ける**。このサイトの核心。
  「美術館でこの絵の前に立ったとき、どこに目を置けばいいか」を、具体的に1〜3文で書く。
  様式の説明ではなく、**その場で目で確かめられること**を書く（筆の跡、光の向き、手の位置、床のタイル、
  修正の跡、画面のどこが不自然か等）。
- 章に1〜2点、`data-spots` で拡大注釈を付ける（見本の《印象、日の出》を参照）。
  `[{"x":62,"y":34,"t":"見出し","d":"説明"}]` の x,y は画像内のパーセント。3点まで。
  **JSON内でシングルクォートを使わない**（属性が壊れる）。
- 著作権：**作者の没後70年を超えた作品のみ画像を出す。** ピカソ、マティス、ウォーホル等、
  権利が生きている作家は `figure.plate` を使わず、`.band.compare` や自作の様式図で扱い、
  「どこで見られるか」を `.seeit` に書く。20〜21世紀の章では特に注意すること。

### 作品マニフェスト（必ず書く）
図版に使ったIDを、**`data/art/<slug>.json`** に1ファイルとして書き出す。他の章と共用しない。

```json
{
  "monet-impression-sunrise": {
    "artist": "クロード・モネ",
    "title": "印象、日の出",
    "year": "1872年",
    "collection": "マルモッタン・モネ美術館（パリ）",
    "commons": "Claude Monet, Impression, soleil levant.jpg",
    "wiki": "印象・日の出",
    "wikiLang": "ja",
    "wikiEn": "Impression, Sunrise",
    "license": "パブリックドメイン"
  }
}
```
- `commons` = Wikimedia Commons のファイル名（`File:` は付けない）。**あなたの知る限り正確に。**
- `wiki` = 日本語版Wikipediaの記事名、`wikiEn` = 英語版の記事名。
  この3つは**独立した3回のチャンス**なので、自信がなくても全部書く。ひとつ当たれば画像が出る。
- 迷ったら英語版Wikipediaの記事名を確実に埋めること（英語版のほうが作品記事が揃っている）。

## 4. 用語と美術館

### 用語
本文で最初に出てくる専門用語を `<span class="term" data-term="筆触分割">筆触分割</span>` で囲む。
1章あたり **4〜8語**。囲んだ語は必ず **`data/terms/<slug>.json`** に定義を書く：

```json
{ "筆触分割": { "short": "絵具をパレットで混ぜず、隣り合わせに置いて、見る人の目の中で混色させる技法。混ぜないので濁らず、画面が明るいままになる。", "chapter": "17-impressionism" } }
```
`short` は **60〜120字**。ツールチップに出るので、1呼吸で読める長さにする。

### 美術館（.seeit）
**「日本で」を必ず先に書く。** 読者は日本にいる。国立西洋美術館、東京国立博物館、大原美術館、
ポーラ美術館、京都国立博物館、奈良国立博物館、根津美術館、MOA美術館、足立美術館、
DIC川村記念美術館、国立新美術館、東京都美術館、寺社（東寺、法隆寺、平等院、中尊寺…）など、
**実際にその章の作品や同種の作品が見られる場所**を、常設か否かも含めて具体的に書く。
知らないことは書かない。確実なものだけ。次に「本場で」を書く。

各項目に Google マップへのリンクを付ける（見本と同じ形）：
```html
<a class="gmap" href="https://www.google.com/maps/search/?api=1&amp;query=施設名" target="_blank" rel="noopener">地図</a>
```
`&` は必ず `&amp;` と書く。

## 5. 最後にやること（自己点検）

1. `node --check` は使えないので、**タグの閉じ忘れと属性のクォート**を目で確認する。
2. `data-art` のIDが `data/art/<slug>.json` のキーと**全部一致**しているか。
3. `.term` の `data-term` が `data/terms/<slug>.json` のキーと**全部一致**しているか。
4. 全 `figure.plate` に `.look` があるか。
5. `.band.spot`（この時代の見分け方）が3枚あるか。
6. `.faces`（この時代の顔）が6〜10点あり、全点に `.hook` があるか。
7. `.seeit` があるか。日本の施設が入っているか。
8. 本文の文字数（タグを除く）が4,000字を超えているか。
9. 絵文字を使っていないか。`<style>` を書いていないか。新しいクラスを発明していないか。

報告は3〜4文で。何を書いたか、図版を何点入れたか、著作権上ぼかした部分があればそれを書く。

## 6. 装飾の境界（守らないと全部やり直しになります）

詳しくは `docs/design/SKIN_RULES.md`。要点だけ:

> **装飾は、本文の領域に入らない。それ以外の場所では思い切りやる。**

- 思い切りやってよい場所：**章扉（門）／全幅の帯（章に1〜2回）／図版の額／見出しと罫線**
- やってはいけないこと：
  - 本文の左右の余白に飾りを**全長にわたって通す**（繰り返すと壁紙になる）
  - **本文の地にテクスチャを敷く**（見えるまで上げると本文が痛む。割に合わない）
  - **本文を枠で囲む**（読む面が分断される）
  - **額が作品より目立つ**（作品がいちばん強い、が絶対条件）
  - 帯を**指示語をまたぐ位置**に置く（「この一文が…」の前に帯を挟むと内容が壊れる）
  - 意味を運ばない**偽のラテン語や漢文の札**を置く
